Visual Coach & Atomic Logic

Real-time ASCII terminal rendering and 100% atomic transaction safety

🚌 Dynamic Visual Seat Maps

The system inspects bus specifications and dynamically formats the physical coach layout in the console:

SEATER (32 Seats - 2x2):
Row 1: [01A] [01B]  |  [01C] [01D]
Row 2: [ XX ] [02B]  |  [02C] [02D]

SLEEPER (24 Berths - Lower/Upper):
Lower: [L01] [L02]  |  [L03]
Upper: [U01] [ XX ]  |  [U03]
[01A] = Available [ XX ] = Booked
🔒 Atomic Multi-Seat Validation

The Problem: When booking seats [1A, 1B, 1C], if seat 1C is already taken, naive systems book 1A & 1B and fail on 1C, leaving partial corrupted state.

Our Solution: Two-Phase Commit Check:
1. Validate all requested seat labels exist.
2. Validate no duplicate labels entered.
3. Verify every seat is currently available.
4. Only if 100% pass, lock seats and create booking.

No Dirty Reads Zero Double-Booking

05 / Data Integrity & Testing ⏱ 3:50 - 4:30 (40s)

Persistence & Crash-Proof Design

CSV engine with zero data loss and bulletproof input sanitization

💾 CSV Persistence Engine

Located in data/buses.csv and data/bookings.csv:

  • Auto-bootstrapping: Preloads sample fleet if files do not exist.
  • Comma-safe: Escapes commas in passenger names and addresses.
  • Immediate flush: Saves state instantly on every booking, cancellation, or route addition.
  • Restart safe: Fully reloads existing fleet and bookings when app restarts.
🛡️ Crash-Proof Input Validation

No unexpected exceptions or crashes. Every input is strictly filtered:

  • Rejects negative or invalid ages (age > 0 && age < 120).
  • Enforces valid gender (M / F / Other).
  • Strict date-time validation using Java 8+ LocalDateTime.
  • Catches InputMismatchException on integer menu choices.
  • Duplicate seat request filtering in single batch bookings.
